# 📈 Pocket Signals

Веб-сервис AI-сигналов (CALL/PUT) для бинарных опционов **Pocket Option**.
ИИ анализирует рыночные данные (RSI, MACD, SMA, Bollinger, тренд, волатильность)
и выдаёт сигнал с уровнем уверенности, таймфреймом, разбором по-русски и ключевыми факторами.

**Главная фишка** — самообучающаяся память: после каждой сделки ИИ записывает урок
(«EURUSD-OTC: RSI перепродан + CALL — сработало, 3/1»), а перед следующими сигналами
релевантные уроки подгружаются в промпт.

> ⚠️ **Дисклеймер:** бинарные опционы — высокорисковый инструмент, можно потерять весь депозит.
> Сигналы не гарантируют прибыль и не являются инвестиционной рекомендацией.
> Честная уверенность ИИ — не «90%+», а реальная сила сигнала.

## 🧱 Стек

| Слой | Что |
|---|---|
| Backend | Python + Flask 3.0, Flask-SQLAlchemy, Flask-Login |
| БД | SQLite локально; **PostgreSQL** на RelaxDev (управляемая БД, `DATABASE_URL` подставляется платформой) |
| Frontend | Jinja2 + vanilla CSS/JS (без фреймворков) |
| ИИ | **dahl.global** (OpenAI-совместимый API), модель `zai-org/GLM-5.3-Flash` |
| Рынок | Живой WebSocket Pocket Option (по SSID пользователя) + честная симуляция как запасной режим |
| Деплой | Docker (gunicorn, порт `${PORT:-8080}`) |

ИИ — **один провайдер (dahl.global)**: Gemini/OpenRouter/Orcarouter удалены по требованию.

## 🔑 Ключи: как и где вводить (важно!)

| Ключ | Где взять | Где вводить | Зачем |
|---|---|---|---|
| **API-ключ dahl.global** | Личный кабинет dahl.global | При входе (блок «🔑 Подключение») или ⚙️ Настройки → «🤖 ИИ» | Без него сигналы не работают |
| **SSID Pocket Option** | DevTools браузера (F12 → Сеть → WS → сообщение `42["auth",...]`) | При входе или ⚙️ Настройки → «📡 Pocket Option» | Живые данные вместо симуляции |

**Ключи сохраняются в профиле пользователя в БД** — при закрытии браузера,
выходе и повторном входе они не пропадают. Сменить/удалить можно в любой момент
в ⚙️ Настройках (там же кнопки «🧪 Тест ключа» и «🧪 Тест подключения»).

### Как скопировать SSID (пошагово)
1. Откройте сайт Pocket Option в браузере и войдите в аккаунт.
2. Нажмите **F12** → вкладка **«Сеть» (Network)** → фильтр **WS**.
3. Кликните на открытое WebSocket-подключение, во вкладке **«Сообщения»**
   найдите сообщение, начинающееся с `42["auth"` (отправляется сразу после загрузки).
4. Скопируйте **всё сообщение целиком** (от `42` до последней `}`) и вставьте
   в поле SSID на сайте.

SSID живёт ограниченное время (обычно ~сутки). Если «🧪 Тест подключения»
начал падать — скопируйте новый SSID.

Приоритет ключа ИИ: **ключ из профиля пользователя → глобальный `DAHL_API_KEY`**
(если задан в конфиге/окружении).

## 🚀 Запуск на RelaxDev (пошагово)

> RelaxDev деплоит проект **из git-репозитория** (GitHub / GitLab / Gitverse / GitFlic).
> Кнопки «загрузить zip» нет, поэтому сначала код кладём в репозиторий.

### Шаг 0 — код в репозиторий
Самый простой вариант (без терминала):
1. На github.com → **New repository** → имя `pocket` → **Private** → Create.
2. На странице нового репо: **«uploading an existing file»** → перетащить в окно
   **все файлы и папки папки `pocket`** (кроме `pocket.zip` и `pocket_signals.db`) → Commit.
   (Вместо GitHub можно GitLab / Gitverse / GitFlic — RelaxDev понимает всех.)

Вариант через git (если выдали токен):
```bash
cd pocket
git init -b main && git add -A && git commit -m "Pocket Signals"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/pocket.git
git push -u origin main
```

### Шаг 1 — создать проект на RelaxDev
1. RelaxDev → **«Добавить проект»** → выбрать свой аккаунт GitHub и репозиторий `pocket`,
   ветку `main`.
2. **Настройка стека: выбрать «Свой Dockerfile»** (НЕ «Автоопределение»!
   автоопределение может решить, что это Next.js, и упасть на package.json).
3. Вкладка **«База данных» → создать PostgreSQL** (один клик, бесплатно).
   Платформа сама пропишет `DATABASE_URL` в переменные — **это обязательно**,
   иначе при каждой пересборке/перезапуске контейнера данные (пользователи,
   ключи, память ИИ) будут теряться: без PostgreSQL используется временный
   SQLite-файл внутри контейнера.
4. Вкладка **«Переменные»** (env):
   | Переменная | Что вписать | Зачем |
   |---|---|---|
   | `SECRET_KEY` | любая длинная случайная строка (32+ символов) | защита сессий |
   | `DAHL_API_KEY` | (опционально) ваш ключ dahl.global | общий ключ ИИ, если пользователи не вводят свой |
   | `PORT` | не задавать | проставляет платформа (8080) |
5. **«Деплой»**. Через пару минут сайт будет на `{имя-проекта}.relaxdev.ru`.
   Проверка: открыть `{имя}.relaxdev.ru/healthz` → `{"status": "ok"}`.

### Шаг 2 — если ИИ или Pocket Option «не отвечают» с платформы
С российских серверов некоторые внешние API недоступны напрямую. RelaxDev решает
это прокси: в поддержке платформы попросить подключить **RELAXDEV_PROXY_URL**
(адрес выдаётся под ваш проект). Платформа сама проставит контейнеру
`HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` — запросы к ИИ (dahl.global) подхватят
прокси автоматически, WebSocket Pocket Option подхватит код приложения.
После этого просто **редеплой** и проверить кнопками «🧪 Тест» в ⚙️ Настройках.

### Что RelaxDev делает сам
- Системный домен `{имя}.relaxdev.ru` с авто-SSL (Let's Encrypt).
- Порт: трафик принимается только на `8080` — приложение читает `PORT`
  из окружения (в нашем Dockerfile: `0.0.0.0:${PORT:-8080}`) — **не прибивать**.
- Авто-перезапуск контейнера при нехватке памяти.
- Логи: вкладка **Runtime Logs**; откаты: **Rollback** в истории деплоев.
- Автодеплой по push в ветку `main` (включается при создании проекта).

## 🚀 Запуск локально

```bash
cd pocket
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python run.py                     # http://localhost:8080
```

Первый старт создаёт БД `pocket_signals.db` и админа:

- **Логин:** `admin`
- **Пароль:** `admin123`  → **смените сразу** в `app/config.py`
  (константы `ADMIN_USERNAME` / `ADMIN_EMAIL` / `ADMIN_PASSWORD`).

Проверка живости: `curl http://localhost:8080/healthz` → `{"status": "ok"}`.

## 🐳 Запуск в Docker

```bash
cd pocket
docker build -t pocket-signals .
docker run -d --name pocket -p 8080:8080 \
  -v pocket-data:/data pocket-signals
```

БД хранится в volume `pocket-data` (`/data/pocket_signals.db` внутри контейнера).
Порт можно переопределить: `-e PORT=9000`.

Для деплой-платформ (RelaxDev): **тип сборки — «Свой Dockerfile»** (в корне лежит
`Dockerfile`, `EXPOSE 8080` на месте). Если платформа подставляет `DATABASE_URL`
(PostgreSQL), он переопределяет SQLite из Dockerfile — данные лягут в постоянную
БД. `PORT` читается из окружения (`0.0.0.0:${PORT:-8080}`), как требует платформа.
Исходящие запросы: `requests` сам использует `HTTP(S)_PROXY` из окружения,
WebSocket PO — через встроенную поддержку прокси (для RELAXDEV_PROXY_URL).

## ⚙️ Бизнес-логика (как задумано)

1. **Регистрация** создаёт заявку: `is_approved=False`. Вход закрыт до
   одобрения (страница «⏳ ожидает одобрения»). Админ одобряет/отклоняет в админке.
2. **Админ** создаётся автоматически при первом старте.
3. **Тарифы:** Free 0₽/3 в день, Basic 990₽/10, Pro 2990₽/50, VIP 9990₽/∞.
   Лимит сбрасывается в полночь. В демо-режиме тариф выбирается на странице
   «Подписка» сразу (без оплаты) или админом в админке.
4. **Получение сигнала** (`/get_signal`): лимит → рынок (живые/симуляция) →
   релевантные уроки памяти → ИИ → сохранение `Signal` → **фоновый тред**:
   ждёт истечения таймфрейма (+10 сек), проверяет результат
   (реальные цены, если SSID жив; иначе — эмуляция, это честно помечается
   в `result_note`) → урок пишется в память.
5. **`/healthz`** — для проверок деплой-платформы.

### Данные рынка
- **LIVE** — SSID задан и PO ответил: реальные 1-минутные свечи (200 шт.),
  индикаторы считаются из них через pandas. На сигнале стоит пометка
  `POCKET OPTION (LIVE)`.
- **SIMULATED** — нет SSID или PO не отвечает (частая причина: **Pocket Option
  блокирует облачные/дата-центровые IP**): честная симуляция с пометкой.
  Сервис при этом работает и учит память (результат сделки — эмуляция, помечено).

## 🩺 Диагностика

| Симптом | Что проверить |
|---|---|
| `ImportError: attempted relative import` / CrashLoop при деплое | В репозитории остался старый код (файл `__init__.py`, папка `app/`). Удалить их в GitHub и залить **новый** набор файлов (плоский, из этого архива). Новый код не содержит относительных импортов и не падает. |
| Деплой собрался, но сервер не нашёл приложение | В настройках проекта: **стек = «Свой Dockerfile»** (не автоопределение!), папка проекта = корень репозитория (где лежит Dockerfile и `app.py`) |
| `DATABASE_URL не задан` в логах сборки | В панели проекта создать PostgreSQL (раздел «База данных») — иначе данные живут во временном SQLite и сгорят при пересборке |
| «Не задан API-ключ ИИ» | Ввести ключ: при входе или ⚙️ Настройки |
| «API-ключ ИИ не принят (401)» | Ключ опечатан/отозван — скопировать заново из dahl.global |
| «ИИ временно перегружен (429)» | Пул модели загружен (статус — на сайте dahl.global). Сайт **сразу** пробует следующую модель из цепочки (GLM → DeepSeek); если обе заняты — подождать минуту. Не жать кнопку много раз подряд: у ключа есть лимит запросов в минуту. |
| «Pocket Option не ответил / отклонил сессию» | SSID просрочен — скопировать новый; либо IP сервера заблокирован PO (просить RELAXDEV_PROXY_URL в поддержке RelaxDev) |
| Сигналы с пометкой SIMULATED | То же: без живого PO работает симуляция |
